Git 워크트리를 지웠더니 가상 환경도 사라졌다

작업을 분리한 워크트리를 제거할 때 Git이 무시하는 파일까지 삭제된 사례와 정리 전에 확인할 범위를 기록했습니다.

우동균·2026.10.28

업무가 겹칠 때 메인 체크아웃에는 진행 중인 변경을 두고, 다른 브랜치는 git worktree add로 별도 디렉터리에 열었습니다. 같은 저장소의 이력을 공유하면서 각 작업에 필요한 브랜치와 파일을 따로 볼 수 있었습니다. 병합이 끝난 워크트리를 git worktree remove로 정리한 뒤, 그 아래에 만들었던 Python 가상 환경 .venv도 함께 사라진 것을 확인했습니다.

워크트리 삭제 전 무시된 파일 확인

워크트리를 제거하면 Git에 등록된 작업 트리와 체크아웃 디렉터리가 정리됩니다. 브랜치 참조는 별도로 남습니다. git status --porcelain이 비어 있으면 커밋되지 않은 변경과 일반 미추적 파일이 있는지 판단할 수 있습니다. 기본 출력에서는 Git이 무시하는 파일을 볼 수 없습니다. 이 사례의 가상 환경처럼 .gitignore에 의해 제외된 파일은 워크트리 디렉터리 아래에 있다면 함께 삭제될 수 있습니다. 그런 파일의 내용은 Git 커밋에도 들어 있지 않습니다.

삭제 전에는 git status --short --ignored로 무시된 경로를 따로 확인할 수 있습니다. 그중 잠금 파일에서 다시 만들 수 있는 가상 환경이나 빌드 산출물과, 다른 곳에 사본이 없는 작업 기록은 구분해야 합니다. 저희는 삭제할 수 있는 워크트리에서 작업을 계속 분리하되, 개인 학습 노트는 메인 체크아웃에만 저장하기로 했습니다.

워크트리를 정리할 때는 작업 브랜치의 커밋이 실제 통합 기준에 들어갔는지 보고, 남은 변경을 확인한 다음, Git이 관리하지 않는 파일까지 훑습니다. 이 사례에서 직접 관측한 것은 워크트리 한 곳을 제거했을 때 가상 환경도 사라진 일입니다. 노트 위치를 정한 이후의 재발 여부는 별도로 확인하지 않았습니다.
