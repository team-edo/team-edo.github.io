업무 결과를 HTTP 응답으로 바꾸기

평가 조회와 녹음 분석 재시도에서 조회·업무 판단·HTTP 응답의 역할을 나누고, 각 경계의 검증 결과를 살펴봅니다.

우동균·2026.10.29

연주 평가를 조회하는 요청은 평가가 있는지, 다른 회원의 세션인지, 아직 분석 중인지에 따라 답이 달라집니다. 분석을 다시 요청할 때도 아직 작업을 시작할 수 없는 경우가 여러 가지입니다. 두 기능에서 예상되는 업무 결과를 이름 있는 값으로 표현하고, HTTP 상태와 응답 본문은 컨트롤러에서 정했습니다.

평가 조회의 판단 경계

컨트롤러는 인증을 마친 토큰에서 회원 ID를 읽어 세션 ID와 함께 넘깁니다. 유스케이스는 조회 계약을 통해 소유한 세션을 찾고, 완료된 세션에서만 평가와 음표 결과를 읽습니다. 세션과 음표 결과는 같은 읽기 전용 트랜잭션에서 조회합니다. 그 계약을 구현한 MyBatis 어댑터는 조회 행을 업무 코드가 읽을 값으로 바꿉니다.

유스케이스가 돌려주는 결과는 NotFound, NotReady, Found입니다. 컨트롤러는 세션을 찾지 못하면 404, 분석이 끝나지 않았으면 409, 평가가 있으면 200으로 응답합니다. 인증 정보가 없는 경우의 401은 보안 필터가 담당합니다. 실제 HTTP와 MySQL을 연결한 테스트에서 이 네 상태를 확인했고, 성공 응답에서는 음표 순서와 점수도 대조했습니다.

재시도 실패를 409와 503으로 구분

분석 재시도에는 규칙상 다시 시작할 수 없는 경우와, 다시 시작할 수 있지만 다른 요청이 계속 먼저 갱신하는 경우가 있습니다. 전자는 NotRetryable, 후자는 Busy입니다. 재시도 유스케이스는 이 둘을 구분해 반환하고, 컨트롤러는 각각 409와 503으로 바꿉니다. sealed interface의 결과를 when 식으로 모두 다루면 결과 종류를 추가할 때 응답 매핑이 빠진 지점을 컴파일 단계에서 발견할 수 있습니다.

단위 테스트에서는 다른 요청이 매번 먼저 시도 번호를 바꾸는 저장소 대역을 만들었습니다. 새 분석을 시작하려는 갱신이 3회 실패한 뒤 결과는 Busy였고 실행기에 제출된 작업은 0건이었습니다. 이 검사는 업무 분기와 제출 여부를 확인했습니다. 503 매핑은 컨트롤러 코드에 있으며, 운영에서 경합이 얼마나 자주 일어나는지는 측정하지 않았습니다.
