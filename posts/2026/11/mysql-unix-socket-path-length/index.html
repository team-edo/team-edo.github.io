130자가 넘는 소켓 경로 때문에 임시 MySQL이 뜨지 않은 이유

macOS에서 폐기용 MySQL이 시작 직후 종료된 로그를 확인하고, 데이터 위치를 유지하면서 소켓 경로만 줄여 기동했습니다.

우동균·2026.11.03
글 수정

macOS에서 마이그레이션을 검증할 폐기용 MySQL 8.4.9를 띄웠습니다. 임시 작업 폴더 안에 데이터와 소켓 파일을 함께 두었는데, 클라이언트가 소켓에 연결하지 못했습니다. 클라이언트 메시지로는 원인을 알 수 없어 MySQL의 시작 로그를 확인했습니다.

연결 오류보다 먼저 기동 로그를 봤다

서버는 The socket file path is too long (> 103)을 남기고 바로 종료됐습니다. 그 실행에서 지정한 소켓의 전체 경로는 130자가 넘었습니다. 여기서 130자는 당시 경로의 문자 길이이고, 오류에 표시된 103은 Unix 소켓 주소에 들어갈 수 있는 바이트 한도입니다.

데이터 디렉터리를 옮기는 대신 --socket으로 지정하는 위치만 짧게 바꿨습니다. 소켓 경로를 바꾸자 데이터 경로를 유지한 상태에서 같은 MySQL이 기동했습니다. 클라이언트가 접속할 때도 변경된 소켓 주소를 사용합니다. 이후 같은 머신에서 임시 DB를 여러 개 띄울 때는 짧으면서도 실행마다 고유한 소켓 이름을 쓰는 조건을 함께 확인할 수 있습니다.

확인한 범위는 해당 macOS 환경에서의 로컬 기동입니다. 경로에 여러 바이트를 쓰는 문자가 들어가면 눈에 보이는 글자 수와 소켓 주소의 바이트 수가 달라질 수 있습니다.
