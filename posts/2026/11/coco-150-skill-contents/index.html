1.5.0 스킬 목차 검사

COCO 스킬 30개의 진입점에 목차를 두고, 본문의 제목을 바꿀 때 목차도 함께 갱신되는지 패키지 검사로 확인했습니다.

1.4.2의 스킬 문서를 보면 coco-research는 한 문단으로 끝나고, coco-build에는 구현과 검증에 필요한 여러 절이 이어졌습니다. 파일을 처음 여는 사람과 에이전트가 읽을 부분을 찾기 쉽도록 1.5.0에서 스킬 30개에 공통 목차를 넣었습니다. 다음으로 풀어야 할 문제는 절 제목이 바뀌어도 목차가 실제 본문을 가리키게 하는 일이었습니다. COCO 1.5.0 변경 기록

목차와 본문 맞추기

목차는 본문의 모든 ## 제목을 등장 순서대로 연결합니다. 문서에 아래와 같은 두 절이 있다면 목차에도 링크가 두 개 들어갑니다.

# 예시 스킬

**Contents:** [입력](#입력) · [검증](#검증)

## 입력

## 검증

나중에 검증을 실행 검증으로 바꾸면 앵커도 #실행-검증으로 바뀝니다. 제목만 고치면 문서는 여전히 읽히지만, 목차 링크는 독자를 해당 절로 데려가지 못합니다. 검증기는 본문에서 앵커 목록을 만들고 목차에 적힌 목록과 순서까지 비교합니다. 본문을 설명하는 코드 블록에 들어간 ## 예시는 이 비교에서 제외합니다. 1.5.0 패키지 검증 코드

한 문단이 전부였던 coco-research에도 Forwarding 절을 뒀습니다. 기존과 같은 스킬로 연결하면서, 짧은 진입점도 같은 방식으로 찾아 읽을 수 있게 한 것입니다.

끊어진 목차 링크 검출

회귀 검사에서 목차를 통째로 지운 파일, 본문 절 이름만 바꾼 파일, 새 절을 목차에서 빠뜨린 파일을 각각 만들었습니다. 세 경우 모두 패키지 검증이 실패해야 합니다. 같은 위치에 코드 블록을 추가하고 블록 안에 ##를 넣은 경우에는 검증이 통과해야 합니다. 목차 회귀 검사

팀에서 스킬을 수정해 사용한다면 절을 바꿀 때 목차 링크도 함께 고쳐야 합니다. 1.5.0의 검증기로 1.4.x 설치물을 검사하면 목차 형식이 없어 실패하므로, 설치된 버전과 검증기 버전을 맞춰 확인합니다. 이 검사로 확인하는 것은 문서의 구조와 링크입니다. 목차가 실제 세션의 읽기 시간이나 토큰 사용량을 얼마나 줄였는지는 측정하지 않았습니다. 1.5.0 호환성 기록
