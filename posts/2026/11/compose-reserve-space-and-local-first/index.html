모드를 바꿔도, 서버를 기다려도 화면이 흔들리지 않게

한 음씩을 켜고 끌 때마다 악보 크기가 바뀌던 문제를 보이지 않는 측정으로 자리를 예약해 고치고, 서버 응답을 기다리던 화면을 이미 가진 데이터로 먼저 보여 주도록 바꾼 과정입니다.

권영민·2026.11.17
이 글의 목차
  • 1. 상태가 바뀌어도 자리 크기는 그대로

    • 같은 생각을 다른 곳에도
  • 2. 서버를 기다리지 않고 먼저 반응하기
    • 운지법 화면이 악기 목록을 기다렸다
    • 예시음은 누를 때마다 서버를 거쳤다
  • 확인한 것과 남은 것

얼쑤의 연습 화면은 정간보를 남은 높이에 맞춰 그립니다. 위에는 제목 줄, 아래에는 플레이어가 있고, 그 사이 남은 높이로 정간 크기와 한 화면에 들어갈 줄 수를 계산합니다. 이 방식 덕분에 기기마다 악보를 꽉 채워 보여 줄 수 있지만, 아래 칸 높이가 조금만 바뀌어도 악보 전체가 다시 배치됩니다.

이번에 고친 것들은 두 갈래였습니다. 하나는 상태가 바뀔 때 화면이 흔들리는 문제, 다른 하나는 서버를 기다리는 동안 화면이 비거나 늦게 반응하는 문제입니다. 구현은 AI 코딩 에이전트와 함께 했고, 저는 고칠 화면을 고르고 동작 기준을 정했습니다.

1. 상태가 바뀌어도 자리 크기는 그대로

한 음씩을 켜면 악보가 커졌다

연습 화면에는 ‘한 음씩’ 스위치가 있습니다. 켜면 아래쪽 플레이어 대신 ‘현재 정간’과 ‘내 연주’ 두 칸, 그리고 평가 버튼이 나옵니다. 이 묶음이 플레이어보다 낮았습니다. 그래서 스위치를 켜면 남은 높이가 늘어나 정간과 운지 그림이 커지고, 끄면 다시 작아졌습니다. 악보를 보며 연습하던 사람에게는 읽던 위치가 움직이는 셈입니다.

작은 휴대폰에서는 같은 일이 더 있었습니다. 연습 페이지, 연주 평가 페이지, 연주 중 화면은 사용자에게 같은 화면인데 위 여백·제목 줄·하단 높이가 조금씩 달랐습니다. 페이지를 옮기거나 연주를 시작하면 정간 크기와 위치가 달라졌습니다.

그리지 않고 재기만 해서 자리를 잡는다

해결 방향은 단순합니다. 아래 칸에 올 수 있는 것들을 모두 재 보고, 가장 높은 것만큼 늘 비워 둡니다. 실제 내용은 그 자리 안 아래쪽에 붙입니다.

Compose에서는 SubcomposeLayout으로 다른 상태의 칸을 구성해 높이만 재고, 배치는 하지 않을 수 있습니다. 아래는 간추린 코드입니다.

SubcomposeLayout(modifier) { constraints ->
    val loose = constraints.copy(minHeight = 0)
    val reserved = subcompose(Reserve, reserve).maxOfOrNull { it.measure(loose).height } ?: 0
    val items = subcompose(Content, content).map { it.measure(loose) }
    val height = maxOf(reserved, items.maxOfOrNull { it.height } ?: 0)
        .coerceIn(constraints.minHeight, constraints.maxHeight)
    layout(constraints.maxWidth, height) { items.forEach { it.place(0, height - it.height) } }
}

한 음씩이 켜져 있을 때 reserve에는 플레이어를, content에는 두 칸과 평가 버튼을 넘깁니다. 플레이어는 재기만 하고 배치하지 않으므로 화면에 보이지 않습니다. 투명도 0으로 그려 숨기면 배치는 되어 자리를 차지하고 화면 읽기 대상에 남을 수 있지만, 이 방법은 높이만 얻습니다. 화면 읽기 기능으로 직접 확인하지는 않았습니다.

연습·평가·연주 중 화면에는 같은 원리로 하단 칸을 만들었습니다. 플레이어와 평가·녹음 막대를 둘 다 재서 높은 쪽만큼 비웁니다. 녹음 막대는 화면 하단에 고정되어 화면 틀이 이미 그만큼 비켜 두기 때문에, 막대가 떠 있을 때는 예약 높이에서 막대 높이를 빼고 비웁니다. 그렇지 않으면 두 번 비게 됩니다.

같은 생각을 다른 곳에도

  • 제목 줄은 오른쪽 스위치가 없는 화면에서도 스위치 높이(44dp)를 최소 높이로 둡니다.
  • 기초 배우기에서 예시음 목록을 받는 동안에는 “불러오는 중” 문구 대신 비활성 버튼을 둬 칸 높이를 지킵니다.
  • 휴대폰 연습 악보의 3소박 정간은 기본 크기에서 곡과 상관없이 66dp(기본 정간의 1.5배)로 맞췄습니다. 긴 각은 정간을 줄이는 대신 두 세로줄로 나누고, 나눠도 모자랄 때만 줄입니다.
  • 불러올 악보 고르기 화면에서는 악기를 고르면 위 카드가 줄어 탭 바가 올라갔습니다. 다른 페이지로 넘어간 것처럼 보여서 탭 바를 맨 위로 옮겼습니다.

모두 “바뀌는 것 때문에 바뀌지 않아야 할 것이 움직이지 않게” 하는 작업입니다.

2. 서버를 기다리지 않고 먼저 반응하기

운지법 화면이 악기 목록을 기다렸다

운지법 보기 화면은 열면 먼저 서버에서 악기 목록을 받았습니다. 목록을 받기 전에는 “불러오는 중” 안내만 보였습니다. 그런데 운지 카드는 앱 안에 들어 있는 운지 데이터로 그립니다. 서버 목록이 꼭 필요한 동작은 다른 악기로 바꾸기 하나뿐이었습니다.

그래서 화면을 열면 처음 악기의 운지 카드를 바로 보여 주고, 목록을 받는 동안에는 악기 고르기 칸만 막았습니다. 목록을 받지 못하면 화면 전체를 안내로 바꾸지 않고 카드 위에 안내와 다시 시도 버튼을 둡니다. 화면 전체를 안내로 바꾸는 경우는 서버 목록에 앱이 운지를 그릴 수 있는 악기가 하나도 없을 때뿐입니다.

여기서 배운 점은 상태를 셋으로 나눠야 한다는 것입니다. 받는 중, 실패, 빈 목록을 한 분기로 처리하면 먼저 보여 줄 수 있는 화면까지 숨기게 됩니다.

예시음은 누를 때마다 서버를 거쳤다

기초 배우기의 ‘음 듣기’ 버튼은 3초 남짓한 예시음을 누를 때마다 서버를 거쳐 받았습니다. 그래서 누른 뒤 소리가 늦게 났습니다. 반대로 할 일을 마치거나 다른 화면으로 옮겨도 소리가 계속 나는 문제도 있었습니다.

예시음을 기기에 받아 두고 다시 쓰도록 바꿨습니다.

  • 파일은 서버가 알려 준 **내용 해시(SHA-256)**로 확인합니다. 주소만으로 캐시하면 서버 파일이 바뀌어도 옛 소리가 납니다.
  • 화면에 보이는 음의 예시음은 미리 받습니다. 그 칸이 화면에서 사라지면 받기를 멈춥니다.
  • 아직 받지 못한 음은 원격 주소로 바로 재생하고, 다음을 위해 받아 둡니다.
  • 받아 둔 파일로 재생에 실패하면, 다시 누를 때 그 파일을 잊고 원격 주소로 재생합니다. 캐시가 고장 나도 한 번 더 누르면 소리가 납니다.
  • 할 일을 마치거나 화면을 옮기면, 재생 중인 소리가 그 화면의 예시음일 때만 멈춥니다.

확인한 것과 남은 것

  • 한 음씩 켜고 끄는 상태·3소박 묶음 계산·악기 목록 상태·예시음 캐시는 자동 테스트로 검사합니다. 하단 자리 예약으로 악보 크기가 유지되는지는 자동 테스트가 없습니다.
  • 화면 크기가 다른 여러 기기에서 모두 확인하지는 않았습니다. 특히 작은 화면일수록 몇 dp 차이가 정간 크기 차이로 커지므로, 큰 기기에서만 보면 놓치기 쉽습니다.
  • 웹에서는 예시음을 기기에 받아 두지 않고 원격 주소로 재생합니다.

두 갈래의 작업은 같은 질문에서 나왔습니다. 사용자가 보고 있는 것을 화면이 먼저 바꿔 버리지는 않는가. 상태가 바뀔 때는 자리를 지키고, 기다릴 때는 이미 가진 것으로 먼저 답하는 쪽으로 정리했습니다.
