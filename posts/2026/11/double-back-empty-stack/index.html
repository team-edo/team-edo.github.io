뒤로 가기를 두 번 눌렀더니 홈 화면이 사라졌습니다

화면 전환 중 남아 있던 버튼이 홈까지 백스택에서 꺼낸 이유와 수정 과정을 정리했습니다.

  • 뒤로 가기를 요청한 항목을 확인하는 방법

얼쑤 웹의 홈에서 AI 연주 평가 시작을 눌러 곡 목록으로 들어갔습니다. 목록의 뒤로 가기 버튼을 빠르게 두 번 눌렀더니 주소는 #home이었는데 화면은 하얗게 비어 있었습니다. 한 번 눌렀을 때는 홈이 보였습니다. 같은 버튼의 두 번째 클릭이 어떤 화면에 적용되는지 확인했습니다.

곡 목록은 보이지만, 백스택에는 이미 홈만 남아 있었습니다

첫 클릭에서 popBackStack()이 곡 목록을 꺼냅니다. 전환 애니메이션이 끝날 때까지 곡 목록과 버튼은 화면에 남아 있지만, 백스택의 맨 위 항목은 이미 홈입니다. 이때 버튼을 다시 누르면 같은 콜백이 현재 맨 위에 있는 홈을 꺼냅니다. 주소가 홈을 가리켜도 NavHost에 그릴 항목이 없습니다.

시점백스택곡 목록 버튼
첫 클릭 전홈 → 곡 목록화면에 보임
첫 클릭 직후홈퇴장 전환 중에 남아 있음
두 번째 클릭 직후비어 있음그릴 화면이 사라짐

뒤로 가기를 요청한 항목을 확인하는 방법

화면 생명주기가 RESUMED일 때만 호출을 받는 방법도 검토했습니다. 프로젝트에서는 분석 화면과 인증 화면처럼 버튼을 누르지 않아도 코드에서 뒤로 가기 콜백을 호출할 수 있었습니다. 그래서 콜백의 출처인 NavBackStackEntry를 넘기고, 그 항목이 여전히 맨 위일 때만 꺼내도록 했습니다.

internal fun NavController.popBackStackFrom(entry: NavBackStackEntry) {
    if (currentBackStackEntry?.id == entry.id) {
        popBackStack()
    }
}

경로 문자열 대신 항목 ID를 비교하면 같은 경로가 백스택에 여러 번 등장해도 어느 항목에서 온 요청인지 구분할 수 있습니다. 첫 클릭으로 곡 목록이 빠진 뒤에는 그 항목의 ID가 홈의 ID와 다르므로 두 번째 호출에서 스택을 건드리지 않습니다.

같은 버튼을 같은 순서로 눌러 봤습니다

수정 전후 모두 홈에서 곡 목록으로 들어가 뒤로 가기를 빠르게 두 번 눌렀습니다. 수정 전에는 흰 화면이 나왔고, 수정본에서는 홈이 그대로 보였습니다. 이 가드는 화면을 꺼내는 요청에 적용됩니다. 이동 버튼을 여러 번 눌러 같은 화면이 중복으로 쌓이는 문제에는 화면을 추가하는 쪽의 처리가 필요합니다.
