정간보 화면에 국악 표기 옮기기

글꼴에 없는 율명, 변 강조색의 대비, 화면에 들어가지 않는 긴 각, 두 연주의 오류 비교를 정간보 화면에서 어떻게 표현했는지 정리했습니다.

권영민·2026.11.13
이 글의 목차
  • 먼저 용어
  • 1. 글꼴에 없는 율명은 변과 율명을 겹쳐 그린다
  • 2. 변 강조색은 대비 두 개를 함께 맞춘다
  • 3. 긴 각은 대강 경계에서 두 줄로 나눈다
  • 4. 이전·이번 오류를 채움과 테두리로 나눈다
  • 한계와 남은 과제

얼쑤는 국악 악보인 정간보를 휴대폰과 태블릿 화면에 그립니다. 종이 악보를 그대로 옮기면 될 것 같았지만, 막상 화면에 올리니 글꼴에 없는 글자, 색으로 구분해야 하는 글자 조각, 화면 높이에 들어가지 않는 줄, 두 번의 연주를 겹쳐 보여 주는 방법을 하나씩 정해야 했습니다.

이 글은 그때 내린 네 가지 결정을 정리한 것입니다. 구현은 AI 코딩 에이전트에게 맡겼고, 저는 시안과 앱 화면을 보며 표현 방식을 정했습니다.

먼저 용어

정간보를 처음 보는 분을 위해 이 글에 나오는 말을 짧게 정리합니다.

용어뜻
율명음 이름입니다. 黃(황), 太(태), 仲(중), 林(임)처럼 한자 한 글자로 적고, 황종에서 몇 반음 떨어졌는지를 나타냅니다. 황의 실제 높이는 악기마다 다릅니다.
정간악보의 네모 한 칸입니다. 한 칸이 정해진 길이의 시간이고, 칸 안에 율명을 적습니다.
각정간을 세로로 이은 한 줄입니다. 위에서 아래로 읽고, 오른쪽 줄에서 왼쪽 줄로 넘어갑니다. 얼쑤 화면에서는 이 세로줄을 ‘각’이라고 부릅니다.
대강장단의 큰 박에 맞춰 한 각의 정간을 묶은 단위입니다. 예를 들어 세마치 장단의 9정간은 3·3·3으로 묶습니다.
청성·탁성한 옥타브 위아래 음입니다. 율명 왼쪽에 변을 붙여 적습니다. 氵가 붙으면 한 옥타브 위(潢 청황), 亻가 붙으면 한 옥타브 아래(㑣 탁임), 氵가 두 번이면 두 옥타브 위입니다.

1. 글꼴에 없는 율명은 변과 율명을 겹쳐 그린다

Compose Web은 기기에 설치된 글꼴로 한글·한자를 대신 그려 주지 않습니다. 그래서 앱 리소스에 글꼴 파일을 넣습니다. 율명과 제목에 쓰는 세리프 글꼴(Noto Serif KR)은 자주 쓰는 한글 2,350자와 율명 한자만 남겨서 넣었습니다. 남긴 율명은 기본 12율명과 潢·汰·淋, 15자입니다.

운지 데이터에 나오는 청성·탁성 글자는 이보다 많습니다. 㑣·㳞처럼 이 15자 밖의 글자는 글꼴에 넣지 않았고, 탁황(僙)처럼 Noto Serif KR에 아예 없는 글자도 있습니다. 이런 글자는 글꼴만으로는 그릴 방법이 없었습니다.

그래서 글자를 변과 기본 율명 두 조각으로 나눠 그리기로 했습니다. 변은 기본 율명보다 작게 그리고, 변 글자 폭의 45%만큼 기본 율명과 겹치게 당겨 붙입니다. 변 글자는 왼쪽에만 획이 있어서 이렇게 겹치면 한 글자처럼 보입니다.

fun glyphPartsOf(hanja: String): HanjaGlyphParts {
    if (hanja in SerifYulGlyphs) return HanjaGlyphParts("", hanja)
    val base = baseYulOf(hanja) ?: return HanjaGlyphParts("", hanja)
    return when (val octave = octaveOf(hanja)) {
        -1 -> HanjaGlyphParts("亻", base)
        1 -> HanjaGlyphParts("氵", base)
        2 -> {
            val oneUp = SerifYulGlyphs.firstOrNull { BaseOf[it] == base && octaveOf(it) == 1 }
            if (oneUp != null) HanjaGlyphParts("氵", oneUp) else HanjaGlyphParts("氵氵", base)
        }
        else -> error("율명 $hanja 의 옥타브 $octave 는 그릴 수 없다")
    }
}

글꼴에 있는 글자는 그대로 쓰고, 없는 글자만 나눕니다. 두 옥타브 위 글자는 한 옥타브 위 글자가 글꼴에 있으면 그 글자에 氵 하나를 더 붙이고(㶂 → 氵 + 潢), 없으면 氵 두 개를 붙입니다. 실제로 그릴 때는 변을 글자 크기의 0.62배, 기본 율명을 0.8배로 그립니다.

조각으로 나눠 그린 덕분에 얻은 것이 하나 더 있습니다. 정간보 쉽게 읽기의 ‘음의 높낮이’ 쪽은 탁황·황·청황을 계단처럼 놓고 변에만 색을 칠합니다. 웹 시안에서는 완성된 한 글자의 왼쪽 약 3분의 1을 잘라 칠했는데, 다른 글꼴로 보이는 기기에서는 경계가 어긋날 수 있었습니다. 앱에서는 변이 별도 글자라서 그 글자에만 색을 주면 됩니다.

2. 변 강조색은 대비 두 개를 함께 맞춘다

변에 칠할 색은 두 가지를 동시에 만족해야 했습니다.

  • 흰 바탕 위에서 글자로 읽혀야 합니다.
  • 바로 옆 검은 율명과 다른 조각으로 구분돼야 합니다.

색을 밝게 하면 검은 율명과는 잘 갈리지만 바탕과의 대비가 떨어집니다. 어둡게 하면 반대가 됩니다. 결국 그 사이의 중간 밝기만 고를 수 있습니다. 대비 계산기는 보통 글자와 바탕만 보기 때문에, 이웃 글자와의 대비는 따로 쟀습니다.

시안의 첫 색은 낙관처럼 붉은 #b8322a였습니다. 서비스 색이 녹색 계열이라 녹색이 나을지 평가해 달라고 했고, 적색약 시뮬레이션(Machado 2009 모델로 근사한 값)에서 빨강은 검은 율명과의 대비가 2.36:1로 떨어졌습니다. 검정과 비슷하게 보인다는 뜻입니다. 그래서 서비스 팔레트의 녹색 후보를 같은 방식으로 쟀습니다. 검은 율명은 시안의 #121212 기준입니다.

후보흰 바탕 대비검은 율명과 대비판단
녹색 #2F5A3C7.93:12.36:1너무 짙어 변이 율명에 묻힘
이끼 #7A984A3.27:15.73:1큰 글자 기준(3:1)을 넘고 율명과 가장 잘 갈림
연두 #9DBF4C2.10:18.91:1흰 바탕에서 글자로 읽기에 너무 연함

가장 짙은 녹색은 바탕 대비가 가장 좋았지만 탈락했습니다. 이끼색은 3.27:1이라 본문 글자 기준(4.5:1)에는 못 미칩니다. 그래서 이 색은 큰 글자에만 쓰기로 하고, 시안의 아래 줄 변을 22px에서 24px로 키웠습니다.

이 조건은 테스트로 고정했습니다. 팔레트가 바뀌어도 두 대비를 다시 검사합니다.

/** 부수 강조색은 24sp 이상 큰 글자에만 쓰므로 큰 글자 기준(3:1)을 본다. 검은 율명과도 구분돼야 한다. */
@Test
fun radicalTintIsReadableAsLargeText() {
    assertReadable("radical / background", colors.radical, colors.background, minimum = 3f)
    assertReadable("radical / text", colors.radical, colors.text, minimum = 3f)
}

앱에 들어간 값은 시안의 #7A984A가 아니라 디자인 보드의 #7E8C1C입니다. 앱의 바탕(#F9FAF9)과 글자색(#27221E)으로 제가 WCAG 식에 넣어 계산해 보면 각각 약 3.55:1, 4.24:1입니다. 테스트가 지키는 것은 특정 색이 아니라 이 두 비율입니다.

3. 긴 각은 대강 경계에서 두 줄로 나눈다

휴대폰의 ‘한 음씩’ 연습 화면에서 단소 아리랑 악보가 유난히 빽빽했습니다. 이 곡은 한 각이 12정간이고, 그중 8칸은 한 정간 안에 음이 세 개씩 들어 있습니다. 이걸 한 세로줄에 모두 넣다 보니 정간 높이가 15dp 안팎까지 줄었습니다.

저는 각을 대강 기준으로 두 줄로 나누고, 각 번호는 첫 줄 위에만 붙이자고 했습니다. 줄을 바꾸는 자리를 화면 크기가 아니라 음악의 박 묶음이 정하게 하려는 것입니다. 구현된 규칙은 이렇습니다.

  • 정간이 6개 이상이고, 한 각이 정해 둔 최소 정간 높이로 한 세로줄에 들어가지 않을 때만 나눕니다.
  • 각 길이가 장단의 정간 수와 같으면, 각의 가운데에 가장 가까운 대강 경계에서 나눕니다.
  • 대강을 모르면 각의 가운데에서 나눕니다.
internal fun columnSplitAt(size: Int, jangdan: Jangdan?): Int {
    val half = (size + 1) / 2
    val starts = jangdan?.takeIf { it.gak == size }?.daegangStarts.orEmpty().filter { it in 1 until size }
    return starts.minByOrNull { kotlin.math.abs(it - half) } ?: half
}

대강마다 시작하는 정간 번호(daegangStarts)는 대강 길이의 누적합으로 구합니다. 세마치 9정간(3·3·3)이면 시작 번호가 0·3·6이고, 가운데(5)에 가까운 6에서 나눠 6+3이 됩니다. 아리랑의 12정간은 6+6이 되고, 3정간씩 끊기는 이 곡의 대강과도 맞습니다.

나누는 것은 그리는 배치뿐입니다. 원래의 각·정간 번호는 그대로 둡니다. 틀린 음 테두리와 율명을 눌러 여는 운지법이 모두 원래 좌표를 기준으로 하기 때문에, 배치를 바꿔도 같은 음을 가리킵니다. 높이가 고정된 연습·평가 화면만 나누고, 세로로 스크롤할 수 있는 틀린 부분 상세 화면은 한 줄로 둡니다.

공통 테스트 1,187개가 통과했고(건너뜀 4개), 웹 앱을 휴대폰 크기로 띄워 단소 아리랑을 직접 확인했습니다. 그 시점에 Android 실기기로는 보지 않았습니다.

4. 이전·이번 오류를 채움과 테두리로 나눈다

‘이전 연주와 비교’ 화면은 같은 곡의 두 연주에서 틀린 정간을 한 악보에 겹쳐 보여 줍니다. 처음 시안은 정간마다 기호를 붙였습니다. ✓ 고친 칸, ● 계속 틀린 칸, ▲ 새로 틀린 칸입니다. 기호가 칸 안의 율명과 겹쳐 보였고, 저는 한때 이번에 틀린 칸만 표시하는 쪽으로 줄였습니다. 그러다 다시 정한 방식은 기호 없이 두 시각 채널을 쓰는 것이었습니다.

  • 이전 연주에서 틀린 정간은 칸을 옅은 붉은색으로 칠합니다.
  • 이번 연주에서 틀린 정간은 붉은 테두리를 두릅니다.
  • 두 번 다 틀리면 칠과 테두리가 함께 나옵니다.
이전이번보이는 모양뜻
틀림맞음바탕만고친 정간
틀림틀림바탕 + 테두리계속 틀린 정간
맞음틀림테두리만새로 틀린 정간

두 집합을 서로 다른 채널에 하나씩 맡기면 겹친 곳이 그대로 교집합이 됩니다. 코드에서도 상태 셋을 두 채널로 풀기만 합니다.

(p.column to p.row) to ScoreCellDecoration(
    fill = if (mark != CompareMark.New) colors.recFaint else null,
    ring = if (mark != CompareMark.Fixed) colors.rec else null,
)

칠한 바탕이 율명을 가리지 않아야 해서 저는 시안에서 두 번 “더 옅게"를 요청했습니다. 시안의 바탕 #F6D5CF는 앱에서 #FDF4F2가 됐고, 테두리는 #C8402F 2dp입니다. 비교는 틀린 위치만 봅니다. 음정이 틀렸는지 박자가 틀렸는지는 구분하지 않습니다.

범례의 숫자는 겹침을 포함합니다. 시안 예시의 ‘이전 연주에서 틀림 12 · 이번 연주에서 틀림 6 · 두 번 다 4’에서 4곳은 앞의 두 숫자에도 들어 있어서, 셋을 더해도 틀린 정간 수가 아닙니다.

한계와 남은 과제

  • 같은 모양, 다른 뜻. 기록이 하나뿐인 기록 상세 화면은 틀린 정간을 옅은 바탕과 테두리로 함께 표시합니다. 비교 화면에서 같은 모양은 ‘계속 틀림’이라서, 화면마다 뜻이 다릅니다.
  • 사용성은 재지 않았습니다. 두 채널이면 범례 없이도 읽힌다는 것은 제 해석이고, 사용자에게 시켜 보고 잰 결과는 없습니다.
  • 강조색 크기 조건. 테스트 주석은 ‘24sp 이상’이라고 적었는데, 계단 그림의 변은 23sp 굵은 글씨로 그립니다. WCAG는 굵은 글씨를 약 18.7px부터 큰 글자로 보지만, 테스트 주석과 실제 크기가 다른 상태라 둘을 맞춰 둘 필요가 있습니다.
  • 대강 정보가 없는 악보. 서버의 공통 악보에는 장단의 대강 정보가 없어서 각의 가운데에서 나눕니다. 이때는 줄바꿈이 박 묶음과 맞지 않을 수 있습니다.
  • 표기 확인. 탁황을 僙으로 적는 것이 팀이 기준으로 삼는 교재와 같은지는 확인하지 못했습니다.

네 가지 모두 종이 악보에는 없던 문제였습니다. 화면에서는 글꼴, 색, 높이가 제약이 되고, 그 안에서 무엇을 지킬지는 국악의 규칙에서 가져왔습니다. 변은 변대로, 줄바꿈은 대강대로, 두 기록은 두 채널대로 나눴습니다.
