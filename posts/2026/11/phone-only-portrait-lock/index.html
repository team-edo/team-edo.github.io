휴대폰만 세로로 묶고 태블릿은 돌게 두기

정간보 한 분절이 휴대폰 가로에 들어가지 않아 휴대폰만 세로로 고정하기로 하고, Android 16의 큰 화면 정책을 피해 실행 중에 기기 최소 너비로 방향을 정한 과정과 에뮬레이터 확인 결과입니다.

얼쑤는 휴대폰과 태블릿을 함께 지원합니다. 화면 배치는 기기 종류가 아니라 지금 앱이 쓰는 창의 너비로 고릅니다. 그런데 화면 방향만은 기기에 따라 다르게 정했습니다. 휴대폰은 연습 화면까지 세로로 고정하고, 태블릿은 세로와 가로를 모두 지원합니다.

이 글은 그렇게 정한 이유와, Android에서 “휴대폰만” 고정하려다 만난 두 가지 함정을 정리합니다. 하나는 Android 16의 큰 화면 정책이고, 다른 하나는 태블릿 에뮬레이터로 휴대폰을 흉내 낼 때의 설정입니다. 구현은 AI 코딩 에이전트와 함께 했고, 방향 정책은 제가 정했습니다.

왜 휴대폰 가로를 막았나

연습 화면의 정간보는 한 각을 대강 경계에서 몇 정간짜리 줄(분절)로 나누고, 분절 하나가 세로 스크롤 없이 한 화면에 보이게 그립니다. 정간 높이는 44dp를 기준으로 삼았습니다. 휴대폰 와이어프레임의 최소값이고 손가락으로 누르기에도 맞는 크기입니다.

결정할 때 기준으로 삼은 가장 긴 분절은 11정간이었습니다. 11정간 × 44dp에 각 머리칸 20dp를 더하면 약 504dp가 필요합니다. 와이어프레임의 머리 영역과 버튼 영역을 빼고 어림한 정간보 높이와 비교하면 이렇습니다.

화면정간보에 쓸 수 있는 높이(어림)약 504dp가 들어가는가들어가는 최대 정간 높이
휴대폰 세로약 550dp들어감약 48dp
휴대폰 가로약 280dp안 들어감약 23dp
태블릿 가로약 640dp들어감약 56dp
태블릿 세로약 980dp들어감약 87dp

휴대폰 가로에서 11정간을 넣으려면 정간 하나가 약 23dp로 줄어듭니다. 한 정간을 두세 음으로 나눈 칸은 한 음이 8~12dp가 되어 보면대에 두고 읽을 수 없습니다. 머리 영역을 거의 없애도 해결되지 않는 크기였습니다.

기기마다 분절을 다르게 자르는 방법도 검토했지만 피했습니다. 화면마다 페이지 경계가 달라지면, 평가 결과의 “3–4각” 같은 위치 표시와 페이지 번호가 기기마다 어긋나기 때문입니다. 그래서 분절은 하나의 규칙으로 자르고, 그 분절이 들어가지 않는 휴대폰 가로를 막기로 했습니다. (이후 줄 나누기 규칙은 최대 12정간으로 정리됐고, 휴대폰 세로에서 긴 줄은 정간 높이를 조금 줄여 넣습니다.)

매니페스트로 고정하면 안 되는 이유

가장 쉬운 방법은 AndroidManifest.xml의 screenOrientation="portrait"입니다. 하지만 이 값은 기기를 가리지 않아서 Android 15 이하 태블릿까지 세로로 묶습니다.

반대로 Android 16부터는 앱이 고정을 요청해도 큰 화면에서 무시됩니다. Android 16 동작 변경 문서에 따르면 API 36을 대상으로 하는 앱은 최소 너비 600dp 이상 화면에서 screenOrientation, setRequestedOrientation() 같은 방향 제한이 무시됩니다. API 36에서는 잠시 끌 수 있는 속성이 있지만, API 37 이상을 대상으로 하면 끌 수 없습니다. 얼쑤의 targetSdk는 37입니다.

정리하면 두 조건이 겹칩니다.

  • 매니페스트 고정은 옛 태블릿까지 묶는다.
  • 새 Android의 큰 화면에서는 어차피 고정이 풀린다.

그래서 태블릿은 처음부터 고정하지 않고, 휴대폰일 때만 실행 중에 고정하기로 했습니다.

실행 중에 기기 최소 너비로 정하기

MainActivity의 onCreate에서 방향을 정합니다.

// 휴대폰(최소 너비 600dp 미만)만 세로로 고정한다. 매니페스트로 고정하면 Android 15 이하 태블릿도 고정되고,
// Android 16부터는 최소 너비 600dp 이상 화면에서 방향 고정이 무시되므로 태블릿은 처음부터 고정하지 않는다.
// 폴더블을 펴거나 화면 분할을 끝내면 액티비티가 다시 만들어지며 이 판정도 다시 한다.
// 다시 만들어진 액티비티는 이전 요청을 이어받으므로 태블릿에서는 고정을 명시적으로 푼다.
private fun lockPortraitOnPhone() {
    requestedOrientation = if (resources.configuration.smallestScreenWidthDp < 600) {
        ActivityInfo.SCREEN_ORIENTATION_PORTRAIT
    } else {
        ActivityInfo.SCREEN_ORIENTATION_UNSPECIFIED
    }
}

두 가지를 신경 썼습니다.

screenWidthDp가 아니라 smallestScreenWidthDp. 지금 창 너비로 판정하면 휴대폰을 가로로 돌렸을 때 너비가 600dp를 넘을 수 있습니다. 판정이 회전에 따라 흔들립니다. 최소 너비는 회전해도 바뀌지 않습니다.

태블릿에서도 UNSPECIFIED를 명시. 액티비티를 다시 만들어도 이전에 요청한 방향이 남습니다. 화면 분할을 끝내거나 폴더블을 펴서 큰 화면이 되었을 때 예전 PORTRAIT 요청이 남아 있으면 곤란합니다. 그래서 아무것도 안 하는 대신 고정을 직접 풉니다.

iPhone은 Xcode 프로젝트의 UISupportedInterfaceOrientations_iPhone을 세로만 두고, iPad는 네 방향을 그대로 두었습니다.

방향 고정과 배치 판정은 따로

방향을 고정해도 화면 배치는 기기 종류가 아니라 창 크기로 고릅니다. 화면 분할, 폴더블, 웹 창에서는 방향과 상관없이 창 너비가 바뀌기 때문입니다. 판정 기준은 공통 코드의 WindowLayout.kt 한 곳에 두었습니다.

이름값뜻
Compact너비 600dp 미만휴대폰 배치
Medium600dp 이상 840dp 미만태블릿 세로 배치
Expanded840dp 이상태블릿 가로·넓은 웹 창
isShortHeight높이 650dp 미만너비는 넓지만 높이가 낮은 창

650dp는 태블릿 가로 배치에서 머리 영역과 여백, 정간 44dp 분절을 더한 높이입니다. 너비만 보면 휴대폰 가로(약 844×390dp)도 Expanded로 판정되므로, 너비가 넓어도 높이가 낮은 창을 가려낼 값이 필요했습니다. 이런 창에서 무엇을 보여 줄지는 아직 정하지 않아, 지금은 판정 값만 제공합니다. 이 판정 함수의 단위 테스트 6개는 Android 호스트·JS·Wasm에서 모두 통과했습니다.

에뮬레이터로 확인하기

태블릿 AVD(2560×1600, 320dpi, 최소 너비 800dp, API 37)에 디버그 빌드를 설치했습니다. 자동 회전을 끄고 settings put system user_rotation 값을 바꿔 돌렸더니, 앱 구성이 w1280dp h800dp land와 w800dp h1280dp port 사이를 오갔고 요청 방향은 UNSPECIFIED였습니다.

휴대폰은 같은 AVD에서 wm size 1080x2400, wm density 420으로 최소 너비를 411dp로 바꾸고 앱을 다시 실행해 봤습니다. 요청 방향은 PORTRAIT로 바뀌었습니다. 그런데 회전시키자 이상한 모습이 나왔습니다. 화면 전체는 가로(2400×1080)로 돌았는데 앱만 w309dp h411dp의 세로 띠로 가운데에 남았습니다. 고정이 안 된 것도, 된 것도 아닌 모습이었습니다.

원인은 태블릿 시스템 이미지의 디스플레이 설정이었습니다.

$ adb shell wm get-ignore-orientation-request
ignoreOrientationRequest true for displayId=0

태블릿 이미지는 앱의 방향 요청을 무시하도록 이 값을 켜 둡니다. 그래서 크기만 휴대폰으로 바꾸면 디스플레이는 돌고 앱은 세로 레터박스로 남습니다. 같은 명령을 휴대폰 AVD에서 실행하면 false가 나왔습니다. 실제 휴대폰도 이 상태를 기대하고 테스트해야 합니다.

wm set-ignore-orientation-request false로 끄고 다시 확인했습니다.

조건결과
자동 회전을 켜고 adb emu rotate 네 번앱은 w411dp h914dp port, 화면은 1080×2400 유지
같은 상태에서 설정 앱 실행2400×1080으로 회전

설정 앱이 도는 것으로 회전 자체는 동작하고 얼쑤만 세로로 남는다는 것을 확인했습니다. 확인 뒤에는 wm size reset, wm density reset, wm set-ignore-orientation-request true로 되돌렸습니다.

확인하지 못한 것

  • Android 15 이하 태블릿. 매니페스트를 쓰지 않았으니 고정되지 않아야 하지만, API 37 이미지에서는 큰 화면의 고정이 어차피 무시되므로 이 차이를 확인할 수 없었습니다.
  • 실기기. 휴대폰·태블릿 실기기, 폴더블 접기·펴기, 화면 분할을 끝낸 직후의 회전은 보지 않았습니다.
  • iOS. Mac이 없어 iPhone 세로 고정과 iPad 회전을 확인하지 않았습니다.

남은 과제

  • 낮은 높이의 창. 납작한 웹 창이나 태블릿 화면 분할에서 정간을 줄일지, 세로 스크롤을 허용할지, 세로 배치로 돌릴지 정해야 합니다.
  • 실기기·iOS 확인. 위의 미확인 항목은 기기를 구하는 대로 확인합니다.

방향 고정은 설정 한 줄로 끝날 줄 알았는데, 실제로는 “어떤 기기에서 고정할지"를 콘텐츠 크기로 먼저 정해야 했습니다. 그다음에는 플랫폼 정책이 그 결정을 어디까지 허용하는지, 그리고 에뮬레이터가 정말 휴대폰처럼 동작하는지를 하나씩 확인해야 했습니다.
